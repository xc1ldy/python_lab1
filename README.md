## Использование

```bash
python -m toolkit calc "2 + 3 * 4"
python -m toolkit calc "(2 + 3) * 4"
python -m toolkit calc "7 // 2"
python -m toolkit calc "7 % 2"
python -m toolkit calc "-5 + 2"
python -m toolkit convert 1000 --from mm --to m
python -m toolkit --help
```

Успешная команда завершается кодом `0` и печатает результат в stdout.
Ошибка печатается в stderr, код завершения — `2`.

## Как устроено вычисление выражения

Вместо разбора выражения рекурсивным спуском, калькулятор переводит
его в обратную польскую нотацию (RPN) и считает стеком (алгоритм
shunting-yard). Путь выражения от строки до числа — четыре шага:

1. **`tokenize()`** (`tokenize.py`) — строка превращается в список
   токенов: числа, операторы `+ - * / // %`, скобки. Пробелы
   игнорируются.
2. **`_resolve_unary()`** (`validation.py`) — токены `+`/`-`
   переклассифицируются в унарные (`NEG`/`POS`) или бинарные в
   зависимости от контекста слева. На этом же шаге проверяется
   структура выражения: два бинарных оператора подряд, отсутствующий
   операнд (в начале, в конце, после `(`, до `)`), пустые скобки —
   каждая ситуация даёт точную ошибку вместо общего сообщения.
3. **`_to_rpn()`** (`validation.py`) — инфиксная запись переводится
   в RPN с учётом приоритетов операций (`// %` — как у `* /`, унарные
   знаки — выше всех) и скобок произвольной вложенности.
4. **`_evaluate_rpn()`** (`calculator.py`) — готовая RPN-
   последовательность вычисляется через стек: число кладётся на
   стек, унарный оператор снимает один операнд, бинарный — два,
   результат кладётся обратно.

`eval`, `exec`, `ast.literal_eval` и сторонние библиотеки парсинга не
используются.

## Обрабатываемые ошибки

| Ситуация | Исключение |
|---|---|
| Пустое выражение | `EmptyExpressionError` |
| Недопустимый символ | `InvalidCharacterError` |
| Два бинарных оператора подряд | `ConsecutiveOperatorError` |
| Не хватает операнда (в т.ч. пустые/незавершённые скобки) | `MissingOperandError` |
| Незакрытая/лишняя скобка | `UnbalancedParenthesesError` |
| Деление на ноль (`/`, `//`, `%`) | `DivisionByZeroError` |
| Некорректное числовое значение (CLI `convert`) | `InvalidNumberError` |
| Неизвестная единица измерения | `UnknownUnitError` |
| Конвертация между разными группами единиц | `IncompatibleUnitsError` |
| Температура ниже абсолютного нуля | `BelowAbsoluteZeroError` |

## Конвертер

Поддерживает три группы единиц (регистр не учитывается):
- **длина**: `mm`, `cm`, `m`, `km` — через приведение к метрам
- **масса**: `g`, `kg` — через приведение к граммам
- **температура**: `c`, `f`, `k` — через приведение к Цельсию

Конвертация между разными группами запрещена, результат всегда
возвращается как `float`.

## Дизайн

- Все ошибки — подклассы `ToolkitError` (`errors.py`), поэтому CLI
  ловит один базовый класс и обрабатывает их одинаково.
- CLI построен на Typer: каждая команда — функция с `@app.command()`.
- Логика разделена по файлам: токенизация, разметка/валидация,
  перевод в RPN и вычисление — каждый шаг в своей зоне
  ответственности.
